## ⚡ The Problem: Why Traditional Sandboxes Fail AI Agents

Autonomous agents (Claude Code, OpenAI Swarm, AutoGen, CrewAI) frequently generate and run arbitrary code to perform data analysis, browse APIs, or solve problems. However:

1. **Docker Containers are too slow**: Standard Docker cold starts take **400ms – 1,500ms**, causing unacceptable latency bottlenecks in high-frequency multi-step agent tool loops.
2. **Naive `eval()` / `exec()` destroys the host**: Running raw code gives agents access to host environment variables (`OPENAI_API_KEY`, `.env`, AWS credentials), filesystem traversal, reverse shell spawning, and fork bombs.
3. **Runaway Loops Hang the Infrastructure**: LLMs frequently produce infinite loops (`while True: ...`) that peg host CPUs at 100% without hardware watchdog supervision.

**SafeBox solves this by providing a sub-millisecond, dual-engine isolation sandbox with hardware watchdog supervision and pre-execution AST static analysis.**

## 🛡️ Security Threat Model & Defense Mechanisms

1. **Host Filesystem Protection (`SEC-002`)**: Detects and rejects any attempt to read `.env`, `.ssh/id_rsa`, `C:\Windows`, or `/etc/passwd`.
2. **Process Spawning Interception (`SEC-001`)**: Intercepts `child_process.execSync`, `spawn`, `subprocess.Popen`, and `os.system`.
3. **Hardware Watchdog SIGKILL**: If untrusted code executes `while (true) {}`, the hardware timer automatically kills the process tree at the exact millisecond threshold requested.
4. **Environment Sanitization**: Child processes inherit zero host environment variables, ensuring host LLM keys or private credentials can never be exfiltrated.
5. **Output Flooding Prevention**: Buffers are hard-capped at 512KB to protect upstream agent parsers from memory exhaustion attacks.
